# Traffic Metrics - Историческое хранение данных графиков

## Обзор

Реализована система сбора и хранения временных рядов трафика для графиков с поддержкой:
- **Фоновый сбор метрик** каждые 10 секунд (даже при закрытой странице)
- **Хранение данных** за последние 24 часа
- **Фильтры периодов**: 30 минут, 1 час, 3 часа, 6 часов, 12 часов
- **Мгновенная загрузка** исторических данных при открытии графика
- **Плавное обновление** в реальном времени

## Архитектура

### Backend

#### 1. Traffic Collector (`app/traffic_collector.py`)
Модуль для сбора и управления метриками трафика:

**Основные функции:**
- `collect_traffic_metrics(clients_data)` - Собирает метрики из данных клиентов
- `load_metrics()` - Загружает метрики из JSON файла
- `save_metrics(metrics)` - Атомарно сохраняет метрики
- `cleanup_old_metrics(metrics, now)` - Удаляет данные старше 24 часов
- `calculate_speed(current_bytes, previous_bytes, time_delta)` - Рассчитывает скорость в MB/s
- `get_metrics_for_period(client_name, minutes)` - Возвращает метрики за указанный период

**Хранимая структура данных:**
```json
{
  "client_name": [
    {
      "timestamp": "2025-10-09T12:00:00+03:00",
      "bytes_received": 1234567,
      "bytes_sent": 234567,
      "speed_rx": 1.5,
      "speed_tx": 0.5
    }
  ]
}
```

**Особенности:**
- Использует `fcntl.flock()` для предотвращения race conditions
- Атомарные операции записи через `tempfile` и `os.replace()`
- Автоматическая очистка данных старше 24 часов
- Рассчитывает скорость на основе разницы байтов между замерами

#### 2. API Endpoint (`app/routes.py`)
**Маршрут:** `/api/traffic-metrics`

**Параметры запроса:**
- `client` (опционально) - Имя конкретного клиента
- `period` (по умолчанию 30) - Период в минутах: 30, 60, 180, 360, 720

**Пример запроса:**
```bash
# Все клиенты за последние 30 минут
curl http://localhost:5000/api/traffic-metrics?period=30

# Конкретный клиент за последний час
curl http://localhost:5000/api/traffic-metrics?period=60&client=user1
```

**Пример ответа:**
```json
{
  "metrics": {
    "user1": [
      {
        "timestamp": "2025-10-09T12:00:00+03:00",
        "bytes_received": 1234567,
        "bytes_sent": 234567,
        "speed_rx": 1.5,
        "speed_tx": 0.5
      }
    ]
  },
  "period_minutes": 30,
  "client": null
}
```

#### 3. Background Logger (`logger.py`)
Интегрирован вызов `collect_traffic_metrics()` в основной цикл:

```python
while True:
    clients = parse_status_log()
    collect_traffic_metrics(clients)  # Сбор метрик
    time.sleep(10)
```

#### 4. Configuration (`app/config.py`)
Добавлена переменная окружения:
- `OPENVPN_TRAFFIC_METRICS` - путь к файлу метрик (по умолчанию: `data/traffic_metrics.json`)

#### 2. JavaScript (`app/static/js/charts.js`)
Добавлены новые функции:

**Загрузка исторических данных:**
```javascript
async function loadHistoricalMetrics(period, clientName = null)
```
- Загружает данные из API `/api/traffic-metrics`
- Возвращает объект с метриками для каждого клиента

**Обработка данных:**
```javascript
function processHistoricalData(metricsData)
```
- Преобразует данные API в формат Chart.js
- Создает единый временной ряд для всех клиентов
- Форматирует метки времени для отображения

**Инициализация графика:**
```javascript
async function initializeChart(users, mode, selectedClient, historicalData)
```
- Теперь асинхронная функция
- Автоматически загружает исторические данные при инициализации
- Заполняет график всеми доступными точками данных
- Рассчитывает статистику (пик, средняя, текущая) для каждого клиента

**Обновление в реальном времени:**
```javascript
function updateChartData(timeLabel, datasetMap, clientName, speedRx, speedTx)
```
- Добавляет новые точки без удаления всех старых
- Ограничивает количество точек на основе текущего периода
- Максимум точек = (период_в_минутах * 60) / 10

**Обработчики фильтров:**
```javascript
// Переключение периода
periodRadios.forEach(radio => {
  radio.addEventListener('change', (e) => {
    currentPeriod = parseInt(e.target.value, 10);
    initializeChart(users, currentChartMode, currentSelectedClient);
  });
});
```

## Использование

### 1. Открытие графика
При открытии модального окна "Traffic Charts":
- Автоматически загружаются исторические данные за последние 30 минут
- График сразу заполнен данными (не нужно ждать 10 секунд)
- Отображается статистика: текущая скорость, пик, средняя

### 2. Фильтрация по периоду
Выберите нужный период:
- **30 минут** - последние 180 точек (10 сек × 180 = 30 мин)
- **1 час** - последние 360 точек
- **3 часа** - последние 1080 точек
- **6 часов** - последние 2160 точек
- **12 часов** - последние 4320 точек

График мгновенно перерисовывается с данными за выбранный период.

### 3. Режимы отображения
**Все клиенты:**
- Показывает графики для всех подключенных клиентов
- Разные цвета для каждого клиента
- Rx (↓) - сплошная линия, Tx (↑) - пунктирная

**По отдельности:**
- Выберите конкретного клиента из выпадающего списка
- Отображаются только его данные
- Включена заливка под графиком
- Показаны точки на графике
- В tooltip отображается детальная статистика

### 4. Статистика
Панель статистики показывает:
- **Текущая Rx/Tx** - скорость в данный момент
- **Пик Rx/Tx** - максимальная скорость за период

## Производительность

### Хранение данных
- **Файл:** `data/traffic_metrics.json`
- **Размер:** ~50-100 KB для 5 клиентов за 24 часа
- **Точек на клиента:** ~8640 точек (24 часа × 360 точек/час)
- **Очистка:** Автоматически каждые 10 секунд удаляются данные старше 24 часов

### Оптимизация
1. **File locking** предотвращает конфликты при чтении/записи
2. **Атомарные операции** через временные файлы
3. **Инкрементальное обновление** - добавляются только новые точки
4. **Ограничение точек** в UI на основе выбранного периода

## Troubleshooting

### График пустой при открытии
**Причина:** Нет собранных данных
**Решение:**
- Подождите 10-20 секунд для сбора первых точек
- Проверьте, что background logger запущен: `docker compose logs -f`

### Нет исторических данных
**Причина:** Файл метрик не создан или поврежден
**Решение:**
```bash
# Проверьте файл метрик
ls -lh data/traffic_metrics.json

# Проверьте права доступа
chmod 644 data/traffic_metrics.json

# Пересоздайте контейнер
docker compose restart
```

### Старые данные не удаляются
**Причина:** Проблема с cleanup_old_metrics()
**Решение:** Проверьте логи background logger на ошибки

### График зависает при обновлении
**Причина:** Слишком много точек данных
**Решение:** Система автоматически ограничивает количество точек на основе периода

## Конфигурация

### Переменные окружения
Добавьте в `docker-compose.yml`:

```yaml
environment:
  # Путь к файлу метрик трафика
  - OPENVPN_TRAFFIC_METRICS=/app/data/traffic_metrics.json
```

### Настройка периода хранения
Отредактируйте `app/traffic_collector.py`:

```python
# Изменить с 24 часов на другое значение
MAX_METRIC_AGE_SECONDS = 48 * 60 * 60  # 48 часов
```

### Настройка интервала сбора
Отредактируйте `logger.py`:

```python
# Изменить интервал с 10 секунд на другой
time.sleep(5)  # 5 секунд
```

## Миграция

При обновлении с предыдущей версии:

1. **Автоматически создается** `data/traffic_metrics.json` при первом запуске
2. **Старые графики** продолжают работать, но без исторических данных
3. **Новые данные** начнут собираться сразу после обновления
4. **Первые 24 часа** график будет заполняться постепенно

## Технические детали

### Thread Safety
- Используется `fcntl.flock()` для file locking
- Один lock файл на operations (`.lock` суффикс)
- Атомарная замена файлов через `os.replace()`

### Формат timestamp
- ISO 8601 с timezone: `2025-10-09T12:00:00+03:00`
- Timezone из `OPENVPN_MONITOR_TZ` (по умолчанию `Europe/Bucharest`)
- Сортировка timestamps лексикографическая

### Расчет скорости
```python
speed_mb_per_sec = (current_bytes - previous_bytes) / (1024 * 1024) / time_delta_seconds
```

- Всегда положительная (используется `max(0, ...)`)
- Точность: 6 знаков после запятой
- Единица измерения: MB/s
