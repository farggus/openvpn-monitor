## Логика работы

1. **Создание сессии**:
   - Клиент подключается к VPN
   - Парсер определяет физический IP адрес
   - Запрашивается геолокация через ip-api.com (бесплатный API, лимит 45 запросов/минуту)
   - Данные сохраняются в `active_sessions.json` с полем `location`

2. **Активные сессии**:
   - Карта на главной странице читает `/api/clients`
   - Данные `location` берутся напрямую из ответа API
   - Нет обращений к внешним сервисам

3. **История сессий**:
   - При закрытии сессии данные переносятся в `session_history.json` вместе с `location`
   - Карта в модале истории читает отфильтрованные записи из `fullHistoryData`
   - Дедупликация по IP - один маркер на уникальный IP
   - Счетчик показывает количество уникальных локаций

## Возможные проблемы и решения

### Проблема: Новые сессии не получают геолокацию
**Решение**: Проверьте доступность API ip-api.com или превышен ли лимит (45 запросов/мин)

### Проблема: Карта истории не показывает маркеры
**Решение**:
1. Проверьте что фильтры не исключают все записи
2. Откройте консоль браузера (F12) и проверьте ошибки JavaScript
3. Убедитесь что в `session_history.json` есть записи с полем `location`

### Проблема: На карте дублируются маркеры
**Решение**: Это не должно происходить благодаря дедупликации по IP в `buildHistoryMap()`

## API для геолокации

Используется бесплатный сервис **ip-api.com**:
- URL: `http://ip-api.com/json/{ip}`
- Лимит: 45 запросов в минуту
- Не требует API ключа
- Возвращает: city, country, latitude, longitude

При превышении лимита или недоступности сервиса, сессия создастся с `location`:
```json
{
  "city": null,
  "country": null,
  "latitude": null,
  "longitude": null
}
```
