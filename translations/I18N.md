# Internationalization (i18n) Guide

Complete guide for working with translations in OpenVPN Monitor.

## Overview

OpenVPN Monitor uses a dual-layer translation system:

- **Backend (Python/Jinja2):** Flask-Babel for server-side translations
- **Frontend (JavaScript):** Custom i18n module via `/api/translations` endpoint

### Supported Languages

| Language | Code | Status | Translator |
|----------|------|--------|------------|
| English | `en` | Default | Built-in |
| Russian | `ru` | Complete | Built-in |
| Romanian | `ro` | Complete | Community |
| German | `de` | Complete | Community |

## Language Selection

### User Interface

Users select language via dropdown in the top-right corner. The selection is:
- Stored in browser cookie (`lang`)
- Persists across sessions
- Applied immediately without page reload

### Detection Priority

1. URL parameter: `?lang=en`, `?lang=ru`, etc.
2. Browser cookie: `lang`
3. HTTP `Accept-Language` header
4. Default: English

### Force Language

```
https://vpn-monitor.example.com/?lang=ru
https://vpn-monitor.example.com/?lang=de
```

## For Developers

### Quick Start

**1. Add translatable string to Python code:**
```python
from flask_babel import gettext as _

message = _("Your text here")
```

**2. Add to Jinja2 template:**
```html
<h1>{{ _('Page Title') }}</h1>
```

**3. Add to JavaScript via API endpoint:**
```python
# In app/routes.py
@app.route("/api/translations")
def translations():
    return jsonify({
        "my_key": _("Translatable text")
    })
```

**4. Use in JavaScript:**
```javascript
alert(t('my_key'));
```

**5. Update translation files:**
```bash
# Extract new strings
pybabel extract -F babel.cfg -o translations/messages.pot .

# Update existing translations
pybabel update -i translations/messages.pot -d translations

# Edit .po files manually
nano translations/en/LC_MESSAGES/messages.po
nano translations/ru/LC_MESSAGES/messages.po

# Compile to .mo files
python translations/compile_translations.py

# Rebuild container
docker compose build
docker compose up -d
```

## Translation Workflow

### Adding New Strings

#### Backend (Python/Jinja2)

**Python code:**
```python
from flask_babel import gettext as _

# Simple string
title = _("Dashboard")

# String with variables (using format)
message = _("Connected at {time}").format(time=timestamp)

# Plural forms
count_msg = ngettext(
    "%(num)d client connected",
    "%(num)d clients connected",
    client_count
) % {'num': client_count}
```

**Jinja2 templates:**
```html
<!-- Simple translation -->
<h1>{{ _('Welcome') }}</h1>

<!-- With variables -->
<p>{{ _('Logged in as') }} {{ username }}</p>

<!-- HTML attributes -->
<input type="text" placeholder="{{ _('Search') }}">
```

#### Frontend (JavaScript)

**Step 1:** Add to `/api/translations` in `app/routes.py`:
```python
@app.route("/api/translations")
def translations():
    return jsonify({
        # Add your keys here
        "confirm_delete": _("Are you sure you want to delete?"),
        "loading": _("Loading..."),
        "error_occurred": _("An error occurred")
    })
```

**Step 2:** Use in JavaScript:
```javascript
// In app/static/js/
if (confirm(t('confirm_delete'))) {
    // delete action
}

document.getElementById('status').textContent = t('loading');
```

### Translation File Format

**Location:** `translations/{lang}/LC_MESSAGES/messages.po`

**Format:**
```po
# Comment explaining context
msgid "Original English text"
msgstr "Translated text"
```

**Example:**
```po
# Dashboard page title
msgid "Active Clients"
msgstr "Активные клиенты"

# Button label
msgid "Disconnect"
msgstr "Отключить"

# Message with variable (don't translate {variable})
msgid "Connected at {time}"
msgstr "Подключен в {time}"
```

**Important:**
- Don't translate placeholder variables: `{variable}`, `%(var)s`, `{0}`, etc.
- Keep HTML tags unchanged: `<b>{name}</b>` → `<b>{name}</b>`
- Maintain line breaks and spacing

## Adding a New Language

### Step 1: Create Directory Structure

```bash
mkdir -p translations/fr/LC_MESSAGES
```

### Step 2: Initialize Translation File

```bash
# Option A: Copy from English
cp translations/en/LC_MESSAGES/messages.po translations/fr/LC_MESSAGES/

# Option B: Generate from template
pybabel init -i translations/messages.pot -d translations -l fr
```

### Step 3: Translate

Edit `translations/fr/LC_MESSAGES/messages.po` and translate all `msgstr` values:

```po
msgid "Active Clients"
msgstr "Clients Actifs"

msgid "Session History"
msgstr "Historique des Sessions"
```

### Step 4: Update Application Code

**Add to `app/routes.py`:**
```python
SUPPORTED_LANGUAGES = ['en', 'ru', 'ro', 'de', 'fr']  # Add 'fr'

@babel.localeselector
def get_locale():
    # ... existing code ...
    if lang in SUPPORTED_LANGUAGES:
        return lang
```

**Add to `app/templates/index.html`:**
```html
<select id="languageSelector">
    <option value="en">English</option>
    <option value="ru">Русский</option>
    <option value="ro">Română</option>
    <option value="de">Deutsch</option>
    <option value="fr">Français</option>  <!-- Add this -->
</select>
```

### Step 5: Compile and Test

```bash
# Compile translations
python translations/compile_translations.py

# Rebuild container
docker compose build
docker compose up -d

# Test in browser
curl http://localhost:5000/?lang=fr
```

## Common Issues

### Translations Not Working

**Symptom:** Interface still shows English

**Solutions:**
1. Check Flask-Babel is installed: `pip list | grep Flask-Babel`
2. Verify translations directory exists in container: `docker exec openvpn-admin ls -la /app/translations`
3. Check browser console for `/api/translations` errors
4. Ensure `.mo` files are compiled: `docker exec openvpn-admin ls translations/ru/LC_MESSAGES/messages.mo`

### Missing Translations

**Symptom:** Some text not translated

**Solutions:**
1. Check if string is wrapped with `gettext()` or `_()`
2. For JavaScript: Add key to `/api/translations` endpoint
3. Extract and update: `pybabel extract` → `pybabel update`
4. Edit `.po` file and compile: `python translations/compile_translations.py`
5. Rebuild container: `docker compose build`

### Language Not Changing

**Symptom:** Dropdown doesn't change language

**Solutions:**
1. Clear browser cookies: `document.cookie.split(";").forEach(c => document.cookie = c.trim().split("=")[0] + "=;expires=" + new Date(0).toUTCString())`
2. Check `lang` cookie in browser DevTools → Application → Cookies
3. Verify language code in `app/routes.py` `get_locale()` function
4. Check JavaScript console for errors in `i18n.js`

### Compilation Errors

**Symptom:** `compile_translations.py` fails

**Solutions:**
1. Check `.po` file syntax: Look for unclosed quotes, missing msgstr
2. Verify Babel is installed: `pip install Babel`
3. Check file permissions: `ls -l translations/*/LC_MESSAGES/*.po`
4. Validate .po file: `msgfmt --check translations/ru/LC_MESSAGES/messages.po`

## Best Practices

### Writing Translatable Strings

✅ **DO:**
- Use full sentences: `_("Client disconnected successfully")`
- Provide context in comments: `# Button label for disconnect action`
- Use placeholders for variables: `_("Connected at {time}")`
- Keep strings self-contained and meaningful

❌ **DON'T:**
- Concatenate strings: ~~`_("Hello") + " " + username`~~
- Split sentences: ~~`_("The client") + _("is connected")`~~
- Use cryptic abbreviations: ~~`_("Conn OK")`~~
- Hardcode HTML in translations: ~~`_("<b>Error:</b> Failed")`~~

### Translation Quality

- **Accuracy:** Translate meaning, not just words
- **Consistency:** Use same terms throughout (e.g., "Client" vs "User")
- **Context:** Consider where text appears (button, heading, error)
- **Length:** Keep translations reasonably close to original length
- **Cultural:** Adapt idioms and metaphors for target culture

### Performance

- Translations are loaded once at startup (backend)
- JavaScript translations fetched once per session
- `.mo` files are cached by Flask-Babel
- Cookie checked on every request (minimal overhead)
