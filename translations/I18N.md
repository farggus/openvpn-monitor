# Localization (i18n) Documentation

This document describes the internationalization setup for OpenVPN Monitor.

## Overview

The project supports multiple languages using:
- **Flask-Babel** for Python/Jinja2 templates
- **Custom API endpoint** (`/api/translations`) for JavaScript

Currently supported languages:
- **English (en)** - default
- **Russian (ru)**

## Language Selection

Users can select their preferred language using the dropdown selector in the top-right corner of the interface. The selection is stored in a cookie (`lang`) and persists across sessions.

Language detection priority:
1. URL parameter `?lang=en` or `?lang=ru`
2. Cookie `lang`
3. Browser `Accept-Language` header
4. Default: English

## For Developers

### Adding New Translations

#### Python/Jinja2 Templates

Wrap translatable strings with `gettext()`:

```python
from flask_babel import gettext

# In Python code
message = gettext("Hello, world!")

# Or use the shorthand
from flask_babel import gettext as _
message = _("Hello, world!")
```

In Jinja2 templates:
```html
<h1>{{ _('Welcome') }}</h1>
<button>{{ _('Submit') }}</button>
```

#### JavaScript

Add the translation key to `/api/translations` endpoint in `app/routes.py`:

```python
translations = {
    "my_new_key": gettext("My translatable text"),
    # ...
}
```

Then use it in JavaScript:
```javascript
alert(t('my_new_key'));
```

### Updating Translations

1. **Add strings** to your code using `gettext()` or `t()` for JS
2. **Update translation files**:
   - Edit `translations/en/LC_MESSAGES/messages.po` (English)
   - Edit `translations/ru/LC_MESSAGES/messages.po` (Russian)
3. **Compile translations**:
   ```bash
   python translations/compile_translations.py
   ```
4. **Rebuild Docker image**:
   ```bash
   docker compose build
   docker compose up -d
   ```

### Translation File Format (.po)

```po
msgid "English text"
msgstr "Русский текст"
```

Example:
```po
msgid "Hello"
msgstr "Привет"

msgid "Loading..."
msgstr "Загрузка..."
```

### Adding a New Language

1. Create directory structure:
   ```bash
   mkdir -p translations/de/LC_MESSAGES
   ```

2. Copy English template:
   ```bash
   cp translations/en/LC_MESSAGES/messages.po translations/de/LC_MESSAGES/
   ```

3. Translate the `msgstr` values in the new file

4. Update `app/routes.py` - add language to `get_locale()`:
   ```python
   if lang in ['en', 'ru', 'de']:  # Add 'de' for German
       return lang
   ```

5. Update language selector in `app/templates/index.html`:
   ```html
   <option value="de">Deutsch</option>
   ```

6. Compile and rebuild

## Testing

1. Start the application:
   ```bash
   docker compose up
   ```

2. Open in browser: `http://localhost:5000`

3. Test language switching using the dropdown selector

4. Verify translations appear correctly in:
   - Page title
   - Navigation buttons
   - Table headers
   - Modal windows
   - Error messages

## Notes

- Translation files are compiled during Docker image build
- Changes to `.po` files require rebuilding the Docker image
- JavaScript translations are loaded asynchronously on page load
- Comments in code (not user-facing text) are NOT localized

## Troubleshooting

**Translations not working:**
- Check that `flask-babel` is installed
- Verify `translations/` directory exists in Docker container
- Check browser console for `/api/translations` errors
- Ensure `.mo` files are compiled (check Docker build logs)

**Missing translations:**
- Add them to `/api/translations` endpoint for JavaScript
- Add them to Python code using `gettext()`
- Update `.po` files and recompile

**Language not changing:**
- Clear browser cookies
- Check `lang` cookie value in browser dev tools
- Verify language code in `get_locale()` function
